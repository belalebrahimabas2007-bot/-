# إنجاز — تطبيق الطلاب ولوحة الإدارة

هذا مستودع جديد ومستقل لمشروع إنجاز، مخصص لتطبيق الطلاب ولوحة الإدارة والخادم المشترك.

## الحالة
المشروع في مرحلة التجربة والتطوير. لا تستخدم بيانات طلاب حقيقية أو معلومات دفع حقيقية قبل مراجعة الأمان والاستضافة.

## التنظيم المخطط
- `student/`: واجهة الطلاب
- `admin/`: لوحة الإدارة
- `server/`: واجهة البرمجة وقاعدة البيانات

> لا علاقة لهذا المستودع بمستودع `mozakerati` السابق.

## متطلبات التشغيل الفعلي

1. إعداد `DATABASE_URL` لقاعدة PostgreSQL دائمة. وضع SQLite الافتراضي للمعاينة المحلية فقط، ولا يصلح لحفظ حسابات أو دفعات حقيقية على استضافة مؤقتة.
2. إعداد خدمة إرسال البريد في بيئة خادم Render، دون حفظ كلمات المرور داخل المستودع. يمكن استخدام إحدى الطريقتين:
   - **Resend HTTPS (الأنسب لـ Render):** توثيق نطاق الإرسال لدى Resend، ثم ضبط `ENGAZ_RESEND_API_KEY` و`ENGAZ_EMAIL_FROM` (مثلاً `إنجاز <verify@yourdomain.com>`). لا تعمل الرسائل إلى جميع الطلاب قبل اعتماد نطاق الإرسال.
   - **SMTP:** ضبط المتغيرات التالية:
   - `ENGAZ_SMTP_HOST`
   - `ENGAZ_SMTP_PORT` (عادة 587 مع STARTTLS أو 465 مع SSL)
   - `ENGAZ_SMTP_USERNAME`
   - `ENGAZ_SMTP_PASSWORD`
   - `ENGAZ_SMTP_FROM`
3. تسجيل الدخول بحساب المسؤول الرئيسي، ثم تحديد سعر كل صف، وإدخال رقم شام كاش ورفع صورة QR الصحيحة من «إعدادات الدفع». لا يمكن إرسال طلب تفعيل قبل اكتمال هذه المعلومات.
4. اختبار رحلة إنشاء الحساب والتحقق من البريد، إرسال طلب التفعيل عبر واتساب، الموافقة اليدوية بعد التحقق من الحوالة، وإدخال كود التفعيل لمرة واحدة.
5. مراجعة الخصوصية والأمان والنسخ الاحتياطي وإعداد إشعارات Push قبل إطلاق المنتج للطلاب. إشعارات Push أثناء إغلاق التطبيق، والمزامنة الكاملة دون إنترنت، وبعض وظائف الحسابات ليست مكتملة بعد.

## فحوصات المشروع

توجد فحوصات آلية لتسجيل الطلاب وتفعيل اشتراك شام كاش في `server/tests/`، وفحص لصحة JavaScript في `.github/workflows/enjaz-checks.yml`. يمكن تشغيل اختبارات الخادم بالأمر:

```bash
python -m pip install -r server/requirements.txt
python -m unittest discover -s server/tests -v
```

> صفحات المعاينة ليست تصريحاً ببدء تحصيل دفعات أو إدخال بيانات طلاب حقيقية قبل استكمال متطلبات التشغيل أعلاه.
